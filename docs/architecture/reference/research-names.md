# Platform and assistant naming screen

Research date: September 24, 2026. This is a preliminary product-name screen, not a claim of trademark, company-name, package-name, or domain availability. No registrations or purchases were made. Search absence means only that no prominent matching product surfaced in these searches.

## Recommendation

**LakeMantle + Sylun** is the strongest working pairing from this screen. LakeMantle expresses a substantial layer around an organization's lake; Sylun is short, soft, and suitable for a small magical guide. The assistant name is a branding suggestion, not a claimed translation or mythological figure.

**LakeMason + Nivru** is the second option, emphasizing building and maintaining a lake. Lake Mason is also a geographic name, so search discoverability is weaker. Nivru is already a personal GitHub handle; this is not a clean namespace claim.

**DataRafter + Vyruli** is a conditional third option if retaining the familiar “Data + construction object” naming pattern matters most. No prominent same-category product using the exact compound surfaced, but Rafter alone has existing software/data-services uses. Do not shorten it to Rafter. DataRivet is removed from the final shortlist because Rivet already names an adjacent AI-agent IDE.

| Rank | Platform / assistant | Intended feel | Screen result and reservation |
|---|---|---|---|
| 1 | **LakeMantle / Sylun** | Enterprise lakehouse platform / calm magical guide | No prominent exact LakeMantle software/data product surfaced. Sylun searches surfaced personal names and game/user handles, not a prominent assistant product. Neither is cleared or registered. |
| 2 | **LakeMason / Nivru** | Lakehouse builder / compact companion | No prominent exact LakeMason software product surfaced; geographic and personal-name noise is significant. Nivru already appears as a GitHub username and unrelated business/name uses. |
| 3 | **DataRafter / Vyruli** | A structure supporting the data workspace / distinctive sprite | No prominent exact DataRafter software product surfaced; **Rafter** has existing software/data-services use. Vyruli searches surfaced unrelated text rather than a prominent AI product; spelling and pronunciation need user testing. |

Suggested pronunciations are **lake-man-tul**, **sil-un**, **lake-may-sun**, **niv-roo**, **data-raf-ter**, and **veer-oo-lee**. These are proposed brand pronunciations.

For the leading option, product labels could be **LakeMantle Workspace**, **LakeMantle SQL**, **LakeMantle Pipelines**, **Sylun**, **Sylun Code**, and **Agent Studio**. Treat these as proposals, not a decision to rename implementation namespaces or prior artifacts.

## Platform candidates screened

The requested similarity is best expressed through a clear data/engineering category and familiar workflows. A near-spelling of Databricks would make differentiation harder; it is unnecessary for usability.

| Candidate | Result | Decision |
|---|---|---|
| LakeMantle | No prominent matching software product found in exact, category, company, and indexed GitHub searches | Lead working candidate |
| DataRivet | Exact compound appeared mainly as unrelated text; Rivet alone is crowded in software and AI | Deprioritize |
| LakeMason | Geographic, personal-name, and handle results; no prominent exact matching software product surfaced | Shortlist |
| DataRafter | No prominent matching exact product surfaced, but results include Salesforce DataRaptor-related spelling noise and Rafter data-services/software uses | Conditional shortlist; less natural to say |
| LakeRivet | No prominent exact matching software product surfaced; shares the Rivet root concern | Reserve |
| DataStave | No prominent exact compound product surfaced; Stave is already used in enterprise software and data storage | Deprioritize |
| Datalith | Prior company-name use appeared in public notices | Deprioritize rather than imply unused |
| DataMason | Existing Data/AI/cloud business and Python data package | Reject |
| DataCairn | Existing AI, analytics, and data-engineering business profile | Reject |
| DataTrestle | Existing database access product for industrial control systems | Reject |
| DataHearth | Established software developer identity across GitHub and package/container ecosystems | Deprioritize |

Direct evidence includes [DataMason](https://datamason.ai/), [DataMason on PyPI](https://pypi.org/project/DataMason/), [DataCairn's business profile](https://in.linkedin.com/company/datacairn), [DataTrestle](https://datatrestle.com/mobile/), and [DataHearth on GitHub](https://github.com/DataHearth). Historical Datalith use appeared in [The Gazette](https://www.thegazette.co.uk/London/issue/60846).

The **Rivet** reservation is concrete: [Ironclad's Rivet](https://github.com/Ironclad/rivet/blob/main/README.md) is an IDE for AI agents and prompt chaining; [Rivet](https://rivet.dev/docs/deploy/) also names a deployment platform. **Stave** is used by [Stave's enterprise applications](https://stavecorp.com/) and by an [Elixir column-based repository](https://docs.elixirtech.com/Ambience/3.5.0/Ensemble/html-multi/ch04s18.html). These do not establish that a longer compound is unavailable; they make it a weaker “unoccupied name” recommendation.

Likewise, the third-choice **DataRafter** needs a reservation: [Rafter's data services](https://rafter.digital/services/data-pipe-lining-services) include data lakes, ETL, and visualization, and [Rafter](https://rafter.readthedocs.io/en/latest/) is also a Python framework. This makes LakeMantle the stronger lead, rather than a claim that every shortlisted name has equal distinctiveness.
