# Durable ingestion outcomes and Delta publication

This contract extends the implemented ingestion and SQL contracts. The outcome and publication lifecycle is implemented and has passed automated backend qualification. It does not claim EKS/S3 production qualification. Publication uses Trino 484's Delta connector with a Hive Metastore or AWS Glue; Polaris remains an independent Iceberg integration.

## Frozen public transport

All routes below are relative to `/api/v1/workspaces/{workspaceId}`. Workspace membership is always required. Publisher mutations additionally require editor access. A publisher can inspect only their own publication operations. Every protected read rechecks current configuration; historical registration does not grant access.

- `GET /runs/{id}/ingestion-outcome` returns `IngestionOutcome` below. It requires the run owner and the currently matching, explicitly granted execution profile. Non-ingestion runs return 404.
- `GET /publication-bindings` returns `{items: PublicationBindingSummary[]}` for current explicitly granted publishers. Summary: `{id,workspaceId,name,policyVersion,pipelineId,executionBindingId,catalog,schema,table,maxRunSeconds}`. No location, endpoint, service identity or credential paths.
- `POST /table-publications` accepts exactly `{runId,bindingId,idempotencyKey}`. Returns 202 `{publication: TablePublication,replayed:boolean}` (same key and exact body recover the original operation). Reuse with another body returns 409. The server requires a succeeded, drained, owned ingestion run with verified nonempty durable outcome and the exact current accepted execution profile. It never re-runs Spark.
- `GET /table-publications` returns `{items: TablePublication[]}` (newest 200, owned and currently authorized).
- `GET /table-publications/{id}` returns one currently authorized owned operation. Changed/revoked publication or execution policy returns 403 without historical details.
- `GET /published-tables` returns `{items: PublishedTable[]}` (at most 1000 configured targets), filtered by current explicit reader grant and current SQL binding grant.
- `GET /published-tables/{id}` returns one `PublishedTable`. The stable table ID is its publication binding ID. This is a current-grant read, not a right conferred by publishing.

`IngestionOutcome`: `{runId,workspaceId,state:"pending"|"verified"|"unavailable",reasonCode?:string,recordedAt?:RFC3339,receipt?:IngestionReceipt,evidence?:{applicationUid,driverUid,driverName,sourceSha256,receiptSha256}}`. Only verified outcomes carry receipt/evidence. `Run.ingestionOutcome` is an optional summary `{state,reasonCode?}`; older runs without the new receipt contract cannot become publishable. Spark success and verified outcome are separate facts.

`IngestionReceipt`: `{version:2,pipelineId,runId,pipelineRevision,receiptBindingSha256,state:"succeeded",runtime:{spark,delta},contractSha256,queryId,completedBatches,processedFiles,processedRows,lastBatchId,tableExists,table}`. Counters and Delta versions are canonical decimal strings; `lastBatchId` is a string or null. `table` is null or `{id,version,schemaSha256,minReaderVersion,minWriterVersion,readerFeatures:string[],writerFeatures:string[]}`. The UUID is runtime-attested, not independently verified by Trino. Counters describe processing, including deduplicated replay; they are not new-row counts. Physical Delta columns are nullable; source validation requirements are a separate contract.

`TablePublication`: `{id,workspaceId,createdAt,updatedAt,revision,bindingId,policyVersion,runId,submittedBy:{issuer,subject},pipeline:{id,revision},target:{catalog,schema,table},deltaVersion:string,state:"queued"|"checking"|"registering"|"verifying"|"published"|"failed"|"unknown",registrationStarted:boolean,reconciliationComplete:boolean,message:string,publishedTableId?:string,verifiedAt?:RFC3339}`. An unknown registration is never automatically resubmitted. While `reconciliationComplete:false`, bounded catalog readback may resolve it; clients keep polling. Once the configured absolute deadline expires, final unknown has `reconciliationComplete:true` and retains its target reservation for operator investigation. Published and failed operations always have `reconciliationComplete:true`. No automatic recovery continues beyond this window. Failure does not promise rollback or deletion.

`PublishedTable`: `{id,workspaceId,name,bindingId,policyVersion,target:{catalog,schema,table},format:"delta",fields:[{name,type,nullable:true}],verifiedDeltaVersion:string,verifiedAt:RFC3339,queryMode:"latest",sql:{bindingId,policyVersion,draft:string}}`. It contains no raw lake location, owner identity, run ID or runtime UUID. SQL is a safely quoted, server-generated bounded preview draft; opening it creates an unsaved editor draft. Saving and execution use existing explicit notebook/query actions. Later compatible appends may be visible; this is not a query of the recorded snapshot.

Errors use the ordinary API envelope. Specific conflicts: `ingestion_outcome_unavailable`, `ingestion_writer_busy`, `publication_schema_unsupported`, `publication_target_busy`, `publication_target_conflict`, `conflict`. Access denial is `forbidden`; unavailable configured capability is `capability_unavailable`. Initial publication supports string, long, double, boolean and date. Timestamp publication is rejected because the pinned reader's default mapping loses Spark timestamp precision.

## Administrator configuration

`DATASLATE_PUBLICATION_BINDINGS_FILE` is a bounded JSON array of exact targets:

`{id,workspaceId,name,policyVersion,pipelineId,executionBindingId,destinationUri,catalog,schema,table,maxRunSeconds,endpoint,caFile?,tokenFile,engineUser,registrationPolicyAccepted:true,allowedPublishers:[{issuer,subject}],readers:[{issuer,subject,sqlBindingId}]}`.

Only canonical S3 prefixes are accepted. Names, targets, pipeline, destination and identities are declared by the administrator, never supplied by browser SQL. Endpoint is HTTPS; credentials are mounted only into the separate publication controller. The read-only SQL identity never receives registration privileges. Matching reader SQL bindings must refer to the same engine endpoint/catalog/schema and independently authorize the exact reader identity; the engine still owns row/column/read-only policy. Policy versions must rotate with restrictive policy changes. Out-of-band engine changes cannot be inferred by the platform.

## Evidence and lifecycle

The generated immutable ingestion configuration includes an opaque hash binding the run, pipeline revision, accepted execution profile and exact ingestion specification. The pinned runtime captures one Delta snapshot after the query finishes, stops Spark, then writes a complete bounded receipt to `/dev/termination-log` with File policy. The controller reads the exact owned terminated driver (exit zero), checks application/driver UIDs and source integrity, validates every receipt binding and persists it before deleting compute. Missing, malformed, replaced or late evidence is unavailable, never inferred from a log tail or exit code. Capture has a bounded deadline; cleanup remains possible when evidence cannot be obtained.

A permanent target reservation binds the configured engine target to its workspace, pipeline and destination. The controller checks for a foreign existing target before recording registration dispatch. It makes one generated registration POST and persists its cursor. A lost response is reconciled with bounded metadata reads, never another registration POST. Success requires exact registered location, recorded Delta version present, expected schema and supported protocol/features. Trino exposes a union of protocol features, not separately verified reader/writer arrays. Compatible later writes may exist. A previously verified DataSlate-owned mapping can be verified for a later successful run without re-registering.

The designated IAM writer boundary and operator admission policy are prerequisites. This does not provide a lock against administrators or arbitrary out-of-band lake writers. No automatic unregister, overwrite, repair, Spark retry or publication cancellation is exposed in this first slice.

The same configured deadline gates registration dispatch and successful finalization, with fresh database clock checks after blocking locks. Readback that completes after this deadline does not manufacture a published receipt. The worker loads publication, execution and SQL binding files; startup validates their relationship without loading provider credentials.

A publication reader grant permits the entire declared column schema, including names of columns that Trino may deny for value access. It grants no row or value access. Administrators must withhold this metadata grant when column names themselves are restricted. Per-reader schema projection requires a future engine-authoritative integration. Engine reservation keys normalize HTTPS default port, hostname case/trailing dot and target-name case; administrators must use one endpoint identity for a given engine because unrelated DNS aliases cannot be inferred.

Publication-enabled ingestion requires a dedicated namespace that is not shared by any configured arbitrary application or notebook binding, including bindings in other workspaces. Receipt capture verifies the actual owned driver image and fixed termination-file policy as well as operator success before and after the read. Cluster administrators remain trusted.

## Backend qualification checkpoint

The frozen backend passed `go test -race ./... -count=1` and `go vet ./...` with verified-TLS PostgreSQL 17.11 and required pgvector 0.8.7. Tests cover durable receipt capture before compute drain, exact runtime hash compatibility, owner/current-policy access, ambiguous registration without resubmission, and permanent target reservations. PostgreSQL regressions hold actual row locks across lease and finalization deadlines and verify that publication rolls back; memory-store tests exercise the same lifecycle. Kubernetes protocol tests reject replaced or foreign drivers, changed operator state, unexpected images and termination policies, malformed receipts and unconfirmed termination. These tests use controlled fixtures; they do not certify an EKS/S3 installation.
