# Airflow workflow contract

This integration targets Apache Airflow **3.4.0**, public REST API v2, with versioned DAG bundles. Airflow owns scheduling and task/whole-workflow retries. DataSlate owns authorization, one durable manual trigger intent and sanitized observation. A manual request does not install a DAG, edit its timetable, backfill, clear tasks, cancel workers or run a second scheduler.

Primary interfaces: [trigger implementation](https://github.com/apache/airflow/blob/3.4.0/airflow-core/src/airflow/api_fastapi/core_api/routes/public/dag_run.py), [run model](https://github.com/apache/airflow/blob/3.4.0/airflow-core/src/airflow/api_fastapi/core_api/datamodels/dag_run.py), [DAG model](https://github.com/apache/airflow/blob/3.4.0/airflow-core/src/airflow/api_fastapi/core_api/datamodels/dags.py), [version model](https://github.com/apache/airflow/blob/3.4.0/airflow-core/src/airflow/api_fastapi/core_api/datamodels/dag_versions.py). Trigger explicitly supplies `bundle_version`; Airflow rejects this when bundle versioning is disabled. An administrator must keep approved bundle content immutable and restrict the broker to exact DAG read/trigger permissions. This does not qualify Airflow 2.x, MWAA or Composer authentication.

## Administrator binding

`DATASLATE_WORKFLOW_BINDINGS_FILE` is a bounded JSON array. Each object has `id`, `workspaceId`, `name`, `policyVersion`, `dagId`, integer `dagVersion`, immutable `bundleVersion`, `airflowVersion:"3.4.0"`, `maxRunSeconds` (60–86400), `endpoint` (root HTTPS), `caFile?`, `tokenFile`, `metadataAccessAccepted:true`, and explicit `allowedSubjects:[{issuer,subject}]`. Token files contain an Airflow-audience bearer token and are reread per request. The API mounts a read-only metadata token; the workflow controller mounts a distinct trigger/read broker token at the same configured token-file path. The broker token is separate from DataSlate API/user tokens and from task service-principal credentials. No passwords or tokens enter project resources. Changing any binding field revokes prior run access; rotating bytes at the same credential path is supported. Administrators must advance `policyVersion` whenever changing a binding’s execution target, scope or behavior, including endpoint, grants and observation limits. Do not reuse a historical policy identity for changed semantics. The reviewed tuple pins the public policy identity; DataSlate cannot infer an out-of-band upstream policy change.

Each allowed subject is explicitly granted the DAG's sanitized schedule, task identifiers/dependencies and **all** scheduled/manual run metadata. This reveals operational timing, version and task names to the team. It does not grant task logs, XCom, conf, rendered templates, source, connections, variables or output values. If those names/times are sensitive, do not grant this binding. Durable DataSlate trigger records remain strictly owner-scoped even for workspace administrators.

## API and shared models

All routes below are under `/api/v1/workspaces/{workspaceId}`. Membership applies to every route; triggering also requires editor/admin. Read/list calls require current exact binding grants. Lists are `{items:[...]}`.

- `GET /workflow-bindings` returns summaries: `{id,workspaceId,name,policyVersion,dagId,dagVersion,bundleVersion,airflowVersion,maxRunSeconds,scheduler:"airflow",retryOwner:"airflow"}`.
- `GET /workflow-bindings/{id}/definition` returns `{bindingId,workspaceId,policyVersion,dagId,dagVersion,bundleVersion,observedAt,paused,stale,hasImportErrors,scheduleSummary,timezone,nextRunAt?,versionMatches,canTrigger,reasonCode,tasks:[{id,downstreamTaskIds:[string]}]}`. Schedule and graph describe the current deployed DAG; `dagVersion`/`bundleVersion` identify the approved trigger version. `canTrigger` requires the current deployed DAG to match that version, be unpaused, nonstale and parse successfully. Graph is bounded to 200 tasks and is not a source editor. A current DAG change blocks new triggers until reviewed/rebound. The backend rechecks admission before the one dispatch.
- `GET /workflow-bindings/{id}/history` returns `{items:[{dagId,backendRunId,state,runType,dagVersion,bundleVersion,logicalDate?,startedAt?,endedAt?}],observedAt,truncated}`. Bounded most recent 50 upstream runs; includes scheduled runs. No DataSlate owner is inferred for upstream scheduled/manual runs.
- `POST /workflow-runs` strict body `{bindingId,idempotencyKey,policyVersion,dagId,dagVersion,bundleVersion}` returns HTTP 202 `{run,replayed}`. All fields are required. The four reviewed policy/DAG fields must exactly match the current authorized administrator binding; they select no arbitrary DAG. A mismatch returns HTTP 409 `workflow_review_changed` before any run is persisted or dispatched. `dagVersion` is an integer from 1 to 1,000,000. An idempotency key is 8–128 letters/digits/dot/underscore/colon/hyphen. Preserve the exact key and complete reviewed tuple after any lost response. Replaying the same owner/key and complete input returns the same durable record only while the exact current binding remains authorized. A changed tuple with a reused key conflicts even when that tuple matches a newly approved binding. No arbitrary conf, schedule or upstream run ID is accepted.
- `GET /workflow-runs` returns owner/current-policy records (latest 200).
- `GET /workflow-runs/{id}` returns one owner/current-policy record.

`WorkflowRun` is `{id,workspaceId,createdAt,updatedAt,revision,bindingId,policyVersion,dagId,dagVersion,bundleVersion,backendRunId,submittedBy:{issuer,subject},state,dispatchStarted,reconciliationComplete,message,observedAt?,startedAt?,endedAt?,tasks:[{id,mapIndex,tryNumber,state,startedAt?,endedAt?}],tasksTruncated}`. States: `queued`, `checking`, `submitting`, `running`, `succeeded`, `failed`, `unknown`. `unknown` with `reconciliationComplete:false` is still being observed. `unknown` with `true` requires operator investigation and **does not mean backend termination**. Succeeded/failed are final only after confirmed upstream state or a definite pre-dispatch admission failure. Failed before dispatch is not a backend failure. `message` explains the distinction. Airflow may queue a submitted run; this is represented as `submitting` until observed running. Tasks may be incomplete when `tasksTruncated:true`; success is based on the authoritative DAG-run state, not on a truncated task list.

## Recovery and security

A PostgreSQL lease/fence protects the sole transition to durable `dispatchStarted`. A generated upstream run ID is unique to the durable DataSlate resource. Conf contains only an exact DataSlate ownership receipt `{dataslate:{runId,workspaceId,bindingId,policyVersion}}`; it contains no source, caller token or arbitrary parameters. Every observed run must match DAG/run ID, complete receipt, expected version and immutable bundle. Conflict, timeout, transport loss and controller restart after dispatch result only in GET readback, never another trigger POST. Failure to observe before the bounded observation deadline yields final unknown; the upstream run may still be active. There is no implicit retry, cancel or delete. Operators investigate through Airflow with its own authorization.

Current policy is reread before dispatch, after network observation and on each response. Policy revocation prevents further engine interaction and owner reads; already-running Airflow tasks require independent credential/permission revocation. Airflow must enforce task execution and lake identities. DataSlate workspace membership is not delegated as authority to run arbitrary code with the trigger broker.
