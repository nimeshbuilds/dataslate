# Authorized lexical and semantic search

DataSlate indexes shared notebook metadata and explicitly granted Polaris table metadata. PostgreSQL full-text search is available without an extension. Hybrid retrieval additionally uses an operator-installed `public.vector` extension and an administrator-approved OpenAI-compatible embedding gateway. It does not index query rows, execution outputs, secrets, storage locations, agents' private memory or raw lake files.

## Profiles and transfer policy

`DATASLATE_SEARCH_BINDINGS_FILE` contains administrator-owned JSON profiles, up to 4 MiB/1,000 bindings. Each profile has `{id,workspaceId,name,policyVersion,mode:"lexical"|"hybrid",sources:{notebooks,includeCellSource,catalogs:[{bindingId,tables:[{namespace,name}]}]},maxDocuments,dataTransferAccepted,embedding?}`.

`maxDocuments` is 1–1,000. Sources are exact, case-sensitive and workspace-scoped. Notebook metadata means name, kind and cell languages. Cell IDs/source code are included only when `sources.includeCellSource:true`, a separate explicit operator choice. Stored code can contain literal secrets; enabling source indexing is a data-classification decision. The default profile should keep it false.

A hybrid profile requires `dataTransferAccepted:true` and `embedding:{endpoint,model,dimensions,caFile?,auth}`. Endpoint is the exact HTTPS embeddings URL, including `/v1/embeddings` when appropriate. Dimensions must be 1–2,000; the model must support the requested dimension. `auth` supports a rotated `bearerTokenFile` or OAuth `clientId`, `clientSecretFile`, `tokenEndpoint`, optional `scope`, and `style:"post"|"basic"`. All credential/CA paths are absolute and server-private. A lexical profile forbids embedding configuration and external-transfer acceptance. Validation makes no provider request.

The explicit transfer approval covers approved indexing payloads and users' hybrid search queries. API pods need embedding credentials for query vectors; the search controller needs embedding credentials for indexing and Polaris credentials for catalog metadata. TLS verification is mandatory. There are no browser-supplied endpoints/credentials, redirect following or ambient environment proxies. CA content rotation requires restart or a changed path. Every embedding request is one POST attempt; neither controller nor adapter retries uncertain outcomes.

## Index lifecycle

Migration `007_search.sql` is extension-free. Notebook save atomically invalidates its old searchable document and updates a durable revision outbox. Notebook deletion cascades its chunks, outbox and notebook indexing jobs. Shared notebook source is never copied into execution outputs to make it searchable. The independent controller synchronizes current notebook revisions for enabled profiles every 30 seconds, prioritizes previously admitted source updates, and filters already attempted exact profile/revision pairs. A new source hitting capacity does not prevent other admitted updates from proceeding. A saved current notebook or an exact catalog identifier can also be indexed with an explicit owner-scoped intent.

The controller acquires a 45-second fenced lease, bounds work to 35 seconds plus up to five seconds for final persistence, and revalidates the current search profile, source revision and catalog grants. Catalog indexing loads real Polaris discovery and safe schema metadata using the requesting exact issuer/subject's grants. A search profile's table allowlist is additional to the metadata binding's table grant. Namespace/table names and validated schema fields are indexed; storage locations, provider configuration and rows are excluded. A catalog snapshot expires after 15 minutes and needs an explicit new indexing intent to refresh. Profile hashes and full catalog authority hashes separate revisions and models. Historical grant snapshots never substitute for current authorization.

Each complete source must fit within 64,000 UTF-8 bytes and 32 chunks of at most 2,000 bytes. Chunk boundaries preserve UTF-8; a source exceeding either limit fails without publication. Nothing is silently truncated and labeled complete. Each profile reserves at most its configured 1–1,000 distinct source slots before embedding; a workspace has at most 100 active jobs. Text/vector publication, job status and source revision checks are atomic. PostgreSQL lease checks use the current wall clock after acquiring locks, so a transaction waiting past expiry cannot publish with an expired lease. Old snapshots cannot replace newer published snapshots.

Before any embedding POST, the controller durably records `embeddingStarted`. If that attempt loses its response, or a controller restarts after recording it, the job becomes `unknown`; it is never resubmitted automatically. An explicit new idempotency key authorizes a new attempt. Provider dimension, finite values, nonzero norms, response model and chunk count are verified before publishing. Source or policy changes during the request discard the returned vectors. Data already dispatched under the earlier valid policy cannot be recalled from a provider; there is no instantaneous external-egress revocation claim.

## Retrieval authorization and ranking

Every request requires current workspace membership. Shared notebook search joins the current source revision. Catalog search intersects current search-source grants with exact current metadata binding grants for the caller. PostgreSQL applies these conditions in a materialized authorization CTE before lexical/vector ranking and before any candidate text leaves the database. The API rechecks current profiles and catalog authority after provider and database calls, then batch-verifies current notebook revisions again before returning snippets. Hits whose source was edited/deleted during retrieval are removed. Missing/malformed policy fails closed. A profile change, table grant change, deletion or notebook revision change prevents old content from returning.

Hybrid retrieval uses exact cosine scoring of bounded authorized chunks, with up to 100 lexical and 100 semantic candidates and reciprocal-rank fusion (`1/(60+rank)`). It emits at most 20 distinct document hits. There is no approximate vector index in this first profile. The hard per-profile document and chunk budgets bound scoring to at most 32,000 authorized chunks. This is a bounded integration, not a claim of large-corpus ANN performance. PostgreSQL types/operators are schema-qualified (`public.vector`, `OPERATOR(public.<=>)`) so a mutable search path cannot substitute another vector type/operator. Operators explicitly install pgvector into `public`; migrations never silently install an extension.

Memory development mode supports approximate lexical matching only and reports vector capability false. PostgreSQL uses the built-in `simple` text-search configuration and `websearch_to_tsquery`. Scores are rankings, not probabilities. Snippets are bounded to 1,200 UTF-8 bytes and may be excerpts. A successful response's `complete:true` means this bounded retrieval request completed; it does not assert all source documents are indexed or exhaustive recall.

## API and receipts

Routes are under `/api/v1/workspaces/{workspaceId}`:

- `GET /search/status` returns `{items:[{id,workspaceId,name,mode,policyVersion,includeCellSource,dataTransferAccepted,vectorAvailable,embeddingModel?,dimensions?}]}`. An unconfigured workspace returns an empty list. It exposes no restricted corpus counts or credential paths.
- `POST /search` takes `{bindingId,query,mode:"lexical"|"hybrid",limit}`. Query is 1–4,096 UTF-8 bytes, nonblank without NUL; limit is 1–20. Hybrid requires an approved profile and pgvector before making a provider request. Lexical performs no embedding request.
- Results are `{bindingId,workspaceId,mode,query,items:[{documentId,kind,title,snippet,score,notebook?:{id,revision},catalog?:{bindingId,namespace,name,policyVersion},indexedAt,expiresAt?}],complete:true}`. Catalog hits include expiry; notebook hits identify the exact current revision.
- `POST /search/index` takes `{bindingId,idempotencyKey,notebook:{id,revision}}` or `{bindingId,idempotencyKey,catalog:{bindingId,namespace,name}}`, never both. Notebook indexing requires workspace editor/admin; catalog indexing requires current exact table grants. New intents return 202, exact owner-scoped replay 200, changed same-key requests 409. Notebook deletion removes its indexing jobs; a deleted-source replay can therefore return 404.
- `GET /search/index-jobs/{id}` returns only the requesting exact issuer/subject's job and requires the current enabled profile/source grants, including exact catalog access. A job has normal resource identity/revision/timestamps, workspace/binding, `submittedBy`, `policyVersion`, the selected notebook or catalog, `state`, `message`, explicit `embeddingStarted`, and optional `documentId`. States are `queued`, `indexing`, `succeeded`, `failed`, `unknown`, `superseded`. System outbox jobs are not user-owned job receipts.

Errors include `403 search_access_denied`, `503 search_policy_unavailable`, `503 search_backend_unavailable`, `501 search_capability_unavailable`, `422 invalid_search`/`invalid_search_index`, `409 search_revision_conflict`/`conflict`, and `429 search_capacity`. Provider details, tokens and request contents are not logged or returned in error messages.

## Deployment and verification

`api/SearchControllerDockerfile` runs `dataslate-search-controller` as nonroot. Required environment is `DATASLATE_DATABASE_URL` with verified TLS and `DATASLATE_SEARCH_BINDINGS_FILE`; `DATASLATE_CATALOG_BINDINGS_FILE` is needed for catalog indexing. `DATASLATE_SEARCH_CONTROLLER_ADDR` defaults to `:8083`. The controller needs no Kubernetes API permissions or service-account token. Readiness checks database schema and loop progress, not provider availability. Migrations remain an explicit operator step.

Tests exercise memory/PostgreSQL lexical lifecycle, pgvector hybrid ranking, exact source/current policy checks, owner-scoped idempotent intents, UTF-8/source bounds, source-slot reservation, metadata-only transfer, current catalog grants/expiry, lost-response and fenced-lease recovery, and a real local TLS embedding gateway. `DATASLATE_TEST_REQUIRE_VECTOR=1` makes missing PostgreSQL or `public.vector` a failure instead of a skipped hybrid test. No paid/external embedding provider or EKS deployment is implied by local tests. Real-world retrieval quality, large-corpus latency, provider cost/token limits, production identities and availability require separate qualification.
