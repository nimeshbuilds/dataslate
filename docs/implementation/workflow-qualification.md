# Workflow qualification evidence

The workflow integration was checked on 2026-11-08 against **Apache Airflow 3.4.0** and PostgreSQL 17. Initial full-suite qualification also required pgvector 0.8.7. This records implemented behavior and its measured scope; it does not certify a complete Kubernetes installation or every Airflow distribution.

## Real execution and product journey

A disposable, loopback HTTPS Airflow installation used a private CA, SimpleAuthManager bearer JWT, LocalExecutor, isolated SQLite metadata and a GitDagBundle pinned to one immutable local commit. The DAG contained three harmless EmptyOperator tasks (`ingest → validate → publish`). Airflow's own scheduler completed scheduled runs. A native Go test separately verified the live version, approved bundle, current schedule, task graph, historical scheduled runs, one durable trigger intent, ownership receipt readback and all three completed tasks.

A browser test then used the real DataSlate handlers, a restricted PostgreSQL runtime role over verified TLS, the separate workflow controller and the real HTTPS Airflow service. It used no browser route interception. The user reviewed the current definition, submitted exactly one manual request, observed all three task completions and the successful DAG run, and reopened the durable record after a browser reload. Independent upstream inspection found exactly one matching run. Development authentication at the loopback DataSlate handler and Airflow's SimpleAuthManager were deliberate test fixtures; production OIDC and exact broker DAG scoping were not established by this journey. EmptyOperator task completion does not establish ingestion/Spark/SQL provider execution in Kubernetes.

The [captured workspace](../assets/workflows-native.png) shows this local EmptyOperator fixture and its actual observed task states; it is not a screenshot of a cloud data pipeline.

## Automated boundaries

- The initial backend snapshot passed all Go packages under `go test -race ./...` against real TLS PostgreSQL with pgvector 0.8.7 required. After the reviewed-intent correction, the complete race suite and `go vet ./...` passed again with TLS PostgreSQL; that separate fixture had no vector extension, so vector-only cases were skipped. Focused workflow regressions exercised both memory and PostgreSQL persistence. CI requires the full suite with pgvector against the final revision.
- Adapter tests cover exact pinned trigger payloads, credential rotation, redirect refusal, bounded/unique JSON, foreign DAG/run/receipt/version rejection, scheduled identifiers, graph/version changes during observation, final pause/stale/import-error admission changes and task identity limits.
- Mandatory reviewed `policyVersion`, `dagId`, `dagVersion` and `bundleVersion` were tested independently: stale approval returns 409 before any persisted or dispatchable run, and changing the tuple cannot reuse the original idempotency key. Missing, untyped and out-of-range versions fail closed. The live Go HTTP and browser journeys were repeated after this correction.
- Memory and PostgreSQL workflow tests cover concurrent idempotency, issuer/subject/workspace isolation, response-loss recovery, durable intent followed by a crash before POST, no resubmission during unknown recovery, current-policy revocation, row-lock lease expiry and observation deadlines. Revocation during run readback prevents the next task metadata request. An observation deadline is represented as unknown, never as worker cancellation.
- The combined workspace browser suite passed **161 tests**, including 24 workflow tests and 137 existing regression tests.
- Five native production controllers (SQL, search, Sylon, publication and workflow) passed verified-TLS/restricted-role startup, multiple idle reconciliation ticks, two starts, graceful shutdown and rejection of insecure PostgreSQL configuration. The runtime role could neither create tables nor mutate the migration ledger. Schema version was 12. The [sanitized controller artifact](../../deploy/workflow-control-plane-qualification.json) records each executable hash and check. These process checks used empty bindings; the separate live workflow journey above tested actual job execution.

## Production container checks

All **eight** current production images (API, execution, SQL, search, Sylon, publication, workflow and web) were built from their pinned bases for `linux/arm64` in an owned containerd VM. The actual containers passed nonroot/read-only-root/capability-drop/no-new-privileges checks. The API rejected missing production authentication and externally exposed development mode. The web container served assets and SPA routes, proxied the API, supplied security headers, refused an invalid upstream and kept callback query credentials out of logs. All six controller containers passed verified-TLS PostgreSQL startup, idle reconciliation, two starts, graceful shutdown and insecure-database refusal. Spark discovery in this check was a TLS protocol fixture, not a Spark operator installation. The [container artifact](../../deploy/workflow-container-qualification.json) records immutable image identities, build-context hashes, checks and limits. No registry push or cloud operation was used.

## Remaining qualification boundaries

KubernetesExecutor task pods, task service-principal authentication, cloud lake identity, external Airflow auth-manager least privilege, queued-work upgrades, complete managed installation, HA, disaster recovery, sustained capacity and production OIDC are separate gates. Airflow 2.x, MWAA and Composer are not silently treated as compatible. Schedules are observed from Airflow; schedule mutation, backfill, clearing tasks and safe worker cancellation are not implemented by this contract. The [workflow contract](workflow-contract.md) documents the exact API, administrator grants and recovery semantics.

The task-owned Airflow services and their database, DAG repository and private CA/JWT material were removed after each native proof. The initial PostgreSQL data directory, private TLS/credential fixtures and three newly installed pgvector files were removed after native controller checks. The separate final container qualification database installed no global extension files; it and its private credentials were removed after the final image checks. The owned Colima VM and container data were deleted and the empty instance list verified. Existing tooling was preserved.
